# TBs dorduncu yol: STEP okuyucuyu kendi icerik ilkesiyle ayri calisanda calistirmak (kart #199)

Yalniz arastirma; depoya kod yazilmadi, tarayicida denenmedi.

## Sonuc
Olur. Onerilen yol **ayri calisan (dedicated worker), ayni kokenden URL ile yuklenen klasik betik**. Worker kendi betik cevabinin CSP basligini kullanir (Chrome 97 ve sonrasi); `unsafe-eval` yalniz o cevabin basliginda olur, ana sayfanin ilkesi degismez (`'unsafe-eval'` yok, `worker-src 'self' blob:` zaten izin veriyor). Worker `blob:`/`data:` ile kurulursa ana sayfanin ilkesini miras alir ve eval yine reddedilir; bu yuzden URL'li dosya sart. Iframe yolu da mumkun ama daha cok parca ister (opak koken, wasm'in postMessage ile gelmesi, koken denetimi); ikinci tercih. Yeniden derleme (a) gerekmez.

## Kaynakli bulgular
1. DOGRULANDI, MDN CSP: "Workers are in general not governed by the content security policy of the document (or parent worker) that created them. To specify a content security policy for the worker, set a Content-Security-Policy response header for the request which requested the worker script itself." Istisna: "if the worker script's origin is a globally unique identifier (for example, if its URL has a scheme of data or blob) ... the worker does inherit". https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy

DOGRULANDI, HTML "create a policy container from a fetch response": blob ise blob URL kaydinin kabi klonlanir, degilse "Set result's CSP list to the result of parsing a response's Content Security Policies given response" (spec metni Ladybird kaynagindaki yorumlardan okundu, html.spec.whatwg.org sayfasi bu bolumde kesildi): https://remotebranch.eu/Stowage/ladybird/src/commit/ddb4bdadd779096ff3f07855b8b2d00a1d211b20/Libraries/LibWeb/HTML/PolicyContainers.cpp

In chrome, they instead used to inherit CSP from the creator document." ve "workers with local schemes (data, blob, filesystem) still inherit". https://chromium.googlesource.com/chromium/src/+/f7c475b89dc0281b63133497efefa6b6cc007c64 ; chromestatus 5715844005888000 "Content-Security-Policy delivery via response headers for dedicated workers", masaustu 97'de cikti: https://chromestatus.com/api/v0/features/5715844005888000

## Iframe yolu (yedek)
Ayri `step-cerceve.html` (kendi basligi: `script-src 'self' 'unsafe-eval'`), `<iframe sandbox="allow-scripts">`; ana sayfanin `frame-src 'self'` uyumlu. Ek is: opak kokende `fetch` CORS ister, wasm baytlari postMessage ile verilmeli; mesaj kokeni `"null"` denetimi; iframe ilkesinde `'self'`'in opak kokende neyle eslestigi dogrulanmadi; ekrana gorunmez cerceve eklenir. Worker'dan cok parca.
